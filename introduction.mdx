## What is TAW?

TAW is a way to build and run custom WordPress sites without a stack of plugins. It's a framework, **taw/core**, with its own data layer: post types, fields and options defined in PHP or JSON, with no ACF. Two themes are built on it: **TAW Theme**, classic and component-based, and **TAW Gutenberg**, a block theme.

Two tools do the everyday work:

<Columns cols="2">
  <Card title="The taw command" href="/taw-command" icon="terminal" horizontal="false">
    `vendor/bin/taw`, inside every theme. It scaffolds blocks, reads and writes fields, moves content between sites, and updates the whole theme in one step with `vendor/bin/taw update`.
  </Card>

  <Card title="taw-fleet" href="/taw-fleet" icon="layout-dashboard" horizontal="false">
    A terminal dashboard for every TAW site on your Mac. It shows versions, git, pull requests, deploys, production health and client feedback, creates sites, and starts Claude Code on a site's skills.
  </Card>
</Columns>

<Callout kind="tip" collapsed="false">
  TAW is for PHP and WordPress developers who like to work in code: PHP classes, Composer and Vite, not page builders.
</Callout>

How the pieces relate, and how a release reaches a live site: [How TAW fits together](/ecosystem).

## Why TAW?

**No ACF, no plugin dependencies: you own your data layer.** The data layer, the metabox engine, forms, mail, image helpers and SVG support are built in, so no third-party field plugin can be abandoned under you. The data works the same way in both themes.

<Columns cols="2">
  <Card title="Updates like a package" href="/updating" icon="refresh-cw" horizontal="false">
    `vendor/bin/taw update` updates taw/core and the framework's files, runs the migrations and the checks, and opens a pull request. The theme's `taw.json` decides what changes, so nothing asks you questions.
  </Card>

  <Card title="One data layer, two themes" href="/data-layer" icon="database" horizontal="false">
    Post types, taxonomies, fieldsets and options pages, defined in PHP or `taw-schema/*.json`. Read them with typed values through `Taw::post()`, or show them in the block editor with Block Bindings.
  </Card>

  <Card title="Data in the block editor" href="/dynamic-tags" icon="braces" horizontal="false">
    Dynamic tags, expressions, conditions, dynamic block settings and the TAW Loop put your fields into any core block, with no custom block code.
  </Card>

  <Card title="Zero-config blocks" href="/taw-core-blocks" icon="layers" horizontal="false">
    In TAW Theme, a block is a folder with a class and a template. `vendor/bin/taw make:block Hero --type=meta --with-style` creates it; each block loads its own CSS and JS only on pages that use it.
  </Card>

  <Card title="Rich metabox engine" href="/taw-core-metabox" icon="list" horizontal="false">
    19 field types, including `repeater`, `group`, `post_select`, `link`, `icon` and `datepicker`, with conditional logic, tabs and grid layouts. The same fields work on options pages, terms and users.
  </Card>

  <Card title="Forms and email" href="/taw-core#forms" icon="mail" horizontal="false">
    `Form` handles CSRF, spam protection, validation, AJAX submission and multi-step wizards. `Mailer` sends transactional email from MJML or HTML templates.
  </Card>

  <Card title="Content that moves" href="/content-interchange" icon="arrow-left-right" horizontal="false">
    `vendor/bin/taw content:export` and `content:import` move a site's content, fields, media and settings as one reviewable JSON file, with a preview first and an undo after.
  </Card>

  <Card title="Production at a glance" href="/taw-fleet-production" icon="satellite-dish" horizontal="false">
    The TAW Companion on each live site answers taw-fleet's signed requests: health, plugin updates, vulnerabilities, logs and published content. No passwords, no SSH.
  </Card>
</Columns>

## Two themes

| | TAW Theme | TAW Gutenberg |
| --- | --- | --- |
| **Kind** | Classic theme | Block theme (full site editing) |
| **Pages are built from** | PHP blocks: MetaBlocks with metabox fields, and UI blocks | Core blocks in the Site Editor, with your fields through Block Bindings and dynamic tags |
| **taw/core boots** | Everything: `Theme::bootstrapFullSite()` | The data layer: `Boot::data()` |
| **`taw` commands** | All 33 | The 6 that don't need the classic scaffold |
| **Front end** | Vite, Tailwind CSS v4, Alpine.js v3 | Vite and TypeScript blocks |

Read more: [TAW Theme](/taw-theme) · [TAW Gutenberg](/taw-gutenberg).

## Get started

<Steps>
  <Step title="Create a site" icon="download" title-type="p">
    With taw-fleet on a Mac with Local:

    ```bash
    brew install Relmaur/tap/taw-fleet
    taw-fleet create "Acme Shop" --classic
    ```

    Or with Composer, in any WordPress install's `wp-content/themes`:

    ```bash
    composer create-project taw/create my-theme \
      --repository='{"type":"vcs","url":"https://github.com/Relmaur/taw-create"}'
    ```
  </Step>

  <Step title="Scaffold a block" icon="terminal" title-type="p">
    ```bash
    vendor/bin/taw make:block Hero --type=meta --with-style
    composer dump-autoload
    ```
  </Step>

  <Step title="Keep it current" icon="refresh-cw" title-type="p">
    ```bash
    vendor/bin/taw update
    ```
  </Step>
</Steps>

The [Quickstart](/quickstart) walks through all of it, including the block's fields and template.
