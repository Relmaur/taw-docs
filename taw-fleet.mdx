`taw-fleet` finds the TAW themes in your Local by Flywheel sites and shows them in one terminal screen. You see which sites run, which themes are behind on taw/core, what's uncommitted or unpushed, and whether a classic theme still matches the taw-theme scaffold. With a few settings it also shows each production site, its pull requests and deploys, and the client's open BugSmash comments.

From the dashboard you open a theme in your editor, update it, hand work to Claude Code in the theme folder, or create a new site. Everything it does also runs on the command line.

## Install

taw-fleet runs on macOS, Apple silicon or Intel.

<Tabs>
  <Tab title="Homebrew" icon="beer">
    ```bash
    brew install Relmaur/tap/taw-fleet
    ```

    Update with `brew upgrade taw-fleet`.
  </Tab>
  <Tab title="Download" icon="download">
    Download `taw-fleet_<version>_darwin_<arm64|amd64>.tar.gz` from the [releases](https://github.com/Relmaur/taw-fleet/releases) and put `taw-fleet` on your `PATH`, for example in `~/.local/bin`.

    Update with `taw-fleet self-update`. It downloads the newest release for this Mac, checks it against the release's `checksums.txt` and replaces the binary. `--check` only says whether a newer one exists.
  </Tab>
  <Tab title="Go" icon="code">
    ```bash
    go install github.com/Relmaur/taw-fleet/cmd/taw-fleet@latest
    ```
  </Tab>
</Tabs>

`self-update` refuses a Homebrew install and tells you to run `brew upgrade taw-fleet`. When a newer release is out, the dashboard shows `▲ <version>` next to its own version.

## First run

<Steps>
  <Step title="Check the fleet" icon="stethoscope">
    ```bash
    taw-fleet doctor
    ```

    You see every TAW site with what needs attention, most serious first, each with its fix: taw/core behind, uncommitted changes, unpushed commits, a broken symlink, a missing PHP build. `doctor` only reads.
  </Step>
  <Step title="Open the dashboard" icon="layout-dashboard">
    ```bash
    taw-fleet
    ```

    It opens in a new window of your terminal and gives the current one back. Press `?` for every key and symbol.
  </Step>
  <Step title="Keep it in this terminal, if you prefer" icon="square-terminal">
    ```bash
    taw-fleet --window=false
    ```

    Or set `window = false` in the settings. When taw-fleet can't open a window, it says why and opens the dashboard where you are. When the output isn't a terminal (piped, CI), `taw-fleet` prints the `list` table instead.
  </Step>
</Steps>

## How it finds sites

There is nothing to set up. taw-fleet reads Local's own files for the current user:

| What | Where |
|---|---|
| Sites | `~/Library/Application Support/Local/sites.json` |
| Running or halted | Live from the Local app while it's open; otherwise Local's `site-statuses.json` |
| TAW themes | Each `wp-content/themes/*/composer.json` that requires `taw/core`. Symlinked themes are followed |
| taw/core installed and locked | The theme's `vendor/composer/installed.json` and `composer.lock` |
| Git state | `git` in the theme folder |
| Newest releases | GitHub tags of taw-core, taw-theme, taw-gutenberg and taw-fleet, cached for an hour |

A theme named `taw/gutenberg`, or a `wordpress-theme` with `theme.json` and `templates/`, is a **block** theme. Any other TAW theme is **classic**.

## The dashboard

One two-line card per TAW theme, with columns for taw/core, the scaffold check, production, BugSmash, pull requests, deploys and git. See [Dashboard and keys](/taw-fleet-dashboard).

## Update a theme

You have four ways, all on [Dashboard and keys](/taw-fleet-dashboard#update-a-theme):

- `u` (`taw-fleet update <site>`) runs `composer update taw/core` and lists the `UPGRADING.md` sections to check.
- `A` hands the whole update to Claude Code in the theme folder, beside the dashboard. `h` shows the prompt first.
- `U` updates every client theme that needs it in one Claude Code session.
- `y` and `S` check a classic theme against the taw-theme scaffold and apply its framework files.

taw-fleet doesn't run `vendor/bin/taw update` yet. For the one-step update, see [Updating a site](/updating).

## Create a site

`n` in the dashboard, or `taw-fleet create`, makes a Local site with a fresh classic or block TAW theme, built, activated and committed. The admin password is shown once. See [Create a site](/taw-fleet-dashboard#create-a-site).

## Settings

Everything is optional: taw-fleet works with no settings file. The file is `~/.config/taw-fleet/config.toml`, or `$XDG_CONFIG_HOME/taw-fleet/config.toml` when that variable is set.

```bash
taw-fleet config init   # write a commented starter file (never overwrites)
taw-fleet config show   # the settings in effect and the apps found
taw-fleet config path   # where the file is
```

```toml title="config.toml"
editor = "Cursor"
terminal = "Ghostty"
window = false
github_owners = ["Relmaur", "EmeLambda"]

[create]
kind = "classic"
admin_user = "marco"
admin_email = "me@example.com"
php = "8.2.30"
web_server = "nginx"

[sites.ls-mxico]
production_url = "https://lsmexico.mx"
notes = "Deploys from main."
bugsmash_project = "a2f16102-91d0-4968-a010-fca3146f4596"

[sites.parallelstaff]
github_account = "parallelstaff"
```

| Key | What it does | Checked when the file loads |
|---|---|---|
| `editor` | The editor for `e`, `w` and `open --editor`. Empty: the first installed of Cursor, Visual Studio Code, PhpStorm, Zed, Sublime Text, Nova. Names are case-insensitive; `code`, `vscode` and `sublime` work too | No. An editor that isn't installed is an error when you open something |
| `terminal` | The terminal for `t`, the dashboard's window, Claude Code and Vite windows. Empty: the first installed of Ghostty, iTerm2, Warp, kitty, Terminal. `iterm` works too. Warp can't run a script, so windows that run something open in Terminal instead | No, same as `editor` |
| `window` | `false` keeps the dashboard in the current terminal. Default `true`. `--window` on the command line wins | Must be a boolean |
| `github_owners` | Your GitHub accounts and organizations. A theme whose repository belongs to another owner is marked `@account` | Must be a list of strings |
| `[create] kind` | `"classic"` or `"block"`: the default theme for new sites | Anything else is an error |
| `[create] admin_user`, `admin_email` | The default WordPress admin for new sites | No; checked when you create a site |
| `[create] php` | A PHP version Local has downloaded, such as `"8.2.30"`. Empty: Local's preferred | No; checked when you create a site |
| `[create] web_server` | `"nginx"` or `"apache"`, optionally with a version. Empty: Local's preferred | No; checked when you create a site |
| `[sites.<folder>] production_url` | The production site. Turns on the LIVE column, `P`, `C`, `live` and `wp-remote` for that site | Must start with `https://` or `http://` |
| `[sites.<folder>] notes` | Free text added to the update prompt `h` and `A` build | No |
| `[sites.<folder>] github_account` | The GitHub account the site's theme belongs to, when it isn't yours (for example before it has a remote) | No |
| `[sites.<folder>] bugsmash_project` | The site's BugSmash project id. Turns on the FB column, `F` and `X`. `taw-fleet comments projects` lists the ids | Must be a UUID |
| `umbrella` | Unused since v1.12.0. It's still accepted so older files load | No |

`<folder>` is the site's folder name in `~/Local Sites`. Any other key is an error that names it (`unknown keys: …`). With a broken file, the dashboard still opens, but its shortcuts are off until you fix it.

## Other GitHub accounts

A theme of another GitHub account shows `@account` in the GIT column and the detail pane, and `/other` filters to those themes. taw-fleet marks a theme when one of these is true:

- Its remote uses an SSH host alias such as `github.com-parallel`, the usual way to use a second account.
- Its repository's owner isn't in `github_owners`. Without `github_owners`, this rule is off.
- The site sets `github_account`, for example for a theme inside a larger repository.

An account listed in `github_owners` is never marked.

## Troubleshooting

<ExpandableGroup>
  <Expandable title="A site shows as halted but it's running" default-open="false">
    Live statuses come from the Local app. With Local closed, taw-fleet falls back to Local's last saved statuses. Open Local and press `r`.
  </Expandable>

  <Expandable title="Start, stop or create says Local isn't open" default-open="false">
    These go through the Local app's own API. Open the Local app and try again.
  </Expandable>

  <Expandable title="A site hangs on start or stop, or Local reports a port conflict" default-open="false">
    Local can leave nginx or php-fpm workers behind whose master is gone. In the dashboard, `s` names them and offers to end them. On the command line, run `taw-fleet unstick <site>`.
  </Expandable>

  <Expandable title="taw/core shows no newest version" default-open="false">
    The newest versions come from GitHub and are cached for an hour. Without network access, taw-fleet uses the last cached answer. If you hit GitHub's rate limit, set `GITHUB_TOKEN` or sign in with `gh auth login`.
  </Expandable>

  <Expandable title="The PR and DEPLOY columns show ?" default-open="false">
    Pull requests and deploys need a GitHub token. Run `gh auth login`, or set `GITHUB_TOKEN`. With `--offline`, the columns don't show at all.
  </Expandable>

  <Expandable title="The editor or terminal doesn't open" default-open="false">
    Check which apps taw-fleet found with `taw-fleet config show`, and set `editor` or `terminal` in the settings.
  </Expandable>

  <Expandable title="The dashboard says its shortcuts are unavailable" default-open="false">
    The settings file doesn't load. Run `taw-fleet config show` to see the error, which names the bad key or value.
  </Expandable>

  <Expandable title="A, X or a says Claude Code isn't installed" default-open="false">
    taw-fleet starts the `claude` command. Install [Claude Code](https://claude.com/claude-code), or use `h` and `c` to copy the update prompt instead.
  </Expandable>
</ExpandableGroup>
